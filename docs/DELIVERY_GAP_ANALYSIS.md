## 0. 一句话结论

方案已经把"怎么做"写清楚了，但**"照着做"还缺三块**：

1. **只有 `:app` 一个模块的构建脚本**——12 个目标模块与 `build-logic` 约定插件全部停留在架构图里；
2. **阶段 1 的实体/DAO 代码与备份格式规范为零**——而这正是方案自己说的"唯一不可压缩阶段"；
3. **12 个决策未定**，其中 5 个会直接卡住阶段 0 开工（轨道、分发渠道、minSdk、存量数据、编译验证环境）。

另外必须坦白一个交付质量问题：**全部骨架代码未经编译验证**。本机 `JAVA_HOME` 指向不存在的路径，无 Android SDK，因此 `libs.versions.toml` 的版本号、`GlassSurface.kt` 的 Haze API 签名都只是"按文档写的"，不是"跑通过的"。

## 5. 需要修正的一处方案内容

`AndroidManifest.xml` 现存两个高危权限，方案未提及：

- `REQUEST_INSTALL_PACKAGES`——用于旧版"应用内下载 APK 自更新"。Play 上属敏感权限（个人开发者基本拿不到），国内商店需书面说明。
- `DOWNLOAD_WITHOUT_NOTIFICATION`——非公开/已废弃权限。

重建后"在线更新"已决定砍掉（方案 5.3），这两个权限**必须一并删除**，否则会在 S-16 合规审核环节被直接卡住。此项已补入方案第 6 章替换表。

### 决策带来的额外风险（新增）

- **开源 + 自持签名** = 密钥保管成为单点。必须做：离线备份 keystore + 口令，且**不得**把 keystore 提交进仓库（.gitignore 已在 S-04 覆盖）。
- **无迁移 + 无存量** 意味着技术上可以自由重命名包名/数据库名——但**用户已决定沿用 `com.huaying.xstz`**（ADR-007）。已记录的连带后果：①同包名 + 不同签名无法覆盖安装旧版（须先卸载）；②未来若上 Google Play，会被要求证明 `com.huaying` 前缀的域名/商标权利，而彼时包名已不可改；③开源发布时易被误认为原项目官方分支。**本项为已决策、非待办**，如日后改主意，越早改成本越低。
- ~~轨 A + compileSdk 37：若 `platforms;android-37` 尚未发布，阶段 0 会被迫退轨 B~~ —— **已由实测取代**：SDK 37 已装且编译通过；且两条轨道的 compileSdk 都只能是 37（ADR-017）。
- **Haze 与 Compose 版本强耦合**：每次调整 `haze` 版本，必须用 `dependencyInsight` 复核 `androidx.compose.ui:ui` 实际解析结果并确认 `compileSdk` 下限——**不能只看 BOM 声明值**（BOM 2026.05 声明 1.11.2，实际被 Haze 顶到 1.12.1）。
- **Gradle 发行包来源受限**：腾讯/阿里镜像均无 9.1.1，官方源在本机超时。当前用本地已缓存的 9.4.1；**换机或接入 CI 时需重新解决发行包获取**（这是阶段 0 的真实外部依赖）。

1. **AGP 每年两次小版本都会改内置 Kotlin**：`kotlin-gradle-plugin` 的 classpath 钉版必须与 AGP 同步复核，否则下次升 AGP 会出现元数据不兼容。
2. **KSP 版本号规则换了**：从 `<kotlin>-<ksp>` 变为独立版本，升级时必须查 KSP 与 Kotlin 的兼容表，不能用"跟着 Kotlin 走"的直觉。
3. **Haze 2.0 是破坏性改版**：1.x 的 `haze-materials` 与 `hazeEffect(state, style)` 在 2.0 全部失效，任何网上搜到的 1.x 示例都不能直接抄。

# Liquid Glass 观感验收标准（v1）

> 本文件把「观感对齐 iOS 液态玻璃 92~95%」这个目标**转换成可测量的判据**。
> 没有这份文件，阶段 2 的验收只能靠"我觉得像/不像"，必然返工。
>
> 适用决策：**验收口径 = 观感对齐**（2026-10-30 确认，不做逐像素对照、不做倾斜高光伪实现）。目标值经 `minSdk 34` 调整：**L3 92~95% / L2 85~88%**（初定为 85~90%）
>
> 关联：`REBUILD_PLAN.md` 第 8 章（视觉方案）、`rebuild/GlassSurface.kt`（材质骨架）、`rebuild/SquircleShape.kt`（形状骨架）

---

## 0. 一句话结论

| 档位 | 综合达成度 | 说明 |
|---|---|---|
| **L3 Full**（API≥34 + 非低端 GPU） | **92~95%** | 模糊 + AGSL 折射 + 动态投影全开，覆盖绝大多数设备 |
| **L2 降级**（低端 GPU / 低电量 / 用户开 Reduce Transparency） | **85~88%** | 降模糊半径、去折射，保留描边与自适应染色 |

> **相比初版的提升**：`minSdk = 34`（ADR-002）使 `RenderEffect`（API 31+）与 AGSL `RuntimeShader`（API 33+）**全设备可用**，原本占 18% 的 `L1 Tint` 档（只有染色、没有模糊，是最"不像 iOS"的一档）彻底消失。因此 L3 目标从 88~92% 上调至 **92~95%**，L2 从 78~82% 上调至 85~88%。
>
> 这是平台门槛的消除，不是参数调整——**同一套代码，在更多设备上都能呈现完整玻璃效果**。

## 1. 评分模型（六维度加权）

总分 = Σ(维度权重 × 该维度达成度)。权重按"对'像不像 iOS'的贡献度"分配，不是按代码量。

| 维度 | 权重 | L3 目标 | 加权得分 | 核心判据 |
|---|---|---|---|---|
| **A 形状**（连续曲率、胶囊、比例） | 15% | 98% | 14.7 | 圆角曲率连续，非圆弧 |
| **B 材质**（模糊、饱和度、噪点） | 25% | 95% | 23.8 | 背景高频消失但明暗可感 |
| **C 边缘**（内高光/外暗边、0.5dp） | 15% | 96% | 14.4 | 上边缘有可测高光带 |
| **D 层级与配色**（只用导航层、染色、投影） | 15% | 92% | 13.8 | 三张极端壁纸下仍可读 |
| **E 动效**（时长、曲线、手感） | 20% | 90% | 18.0 | 时长误差 ≤±30ms，曲线为 iOS ease-out |
| **F 排版**（字重、字距、等宽数字） | 10% | 92% | 9.2 | 数字变化不横向跳动 |
| **合计** | 100% | | **93.9%** | |

**E 维度扣分说明**：其中「高光随姿态响应」占 E 的 15%（总分 3%），实际只能做到 30%，因此 E 从 100% 扣至 88%。这是**已知且已接受**的损失，不视为缺陷。

## 2. 逐维度验收细则

### A · 形状（权重 15%，目标 97%）

**必须达到的规格**

| 元素 | 圆角 | 超椭圆指数 n | 备注 |
|---|---|---|---|
| 卡片 / 列表容器 | 20dp | **2.8** | UI 元素用 2.8 |
| Sheet / 模态 | 28dp | **2.8** | |
| 胶囊按钮 / Tab 选中态 | 高度的一半 | 退化（n=2.0） | 全圆端，不用 squircle |
| **App 图标底板** | 系统决定 | **4.0~5.0** | 仅图标，**不得**用于 UI 圆角 |

> 修正记录：方案 8.3 原文写「指数 n≈4~5」，语境为"所有圆角"，与 `SquircleShape.kt` 的默认值 2.8 冲突。
> 正确结论：**UI 圆角 n=2.8，图标底板 n=4.0~5.0**，两者不可混用。n=4~5 用在卡片上会明显偏方。

**测量方法**

1. 截取一个 100×100dp 玻璃卡片的左上角区域；
2. 沿 45° 对角线，测量轮廓交点距理论角点的距离 `d`，除以圆角半径 `r`；
3. 参考值：理想圆弧 `d/r = √2−1 ≈ 0.414`；`n=2.8` 超椭圆 `d/r ≈ 0.36`（比圆弧饱满约 13%）；`n=4.5` 约 `0.30`（过方）。

**通过线**

- `d/r` 落在 **0.34~0.38** 区间；
- 放大 800% 沿圆弧检查，**无曲率突变折点**（圆弧方案在直线与弧的接缝处必然有折点）。

---

### B · 材质（权重 25%，目标 92%）

**唯一材质来源：`CupertinoMaterials`**——这是 Apple 自己的四档材质参数，直接复用，**不自行调参拟合**。

| 场景 | CupertinoMaterials | Haze 模糊半径 | 饱和度提升 |
|---|---|---|---|
| 顶栏 / 底栏 | `regular()` | 24dp（L3）/ 18dp（L2） | 1.5~1.8× |
| Sheet / 模态 | `thick()` | 24dp | 1.4~1.6× |
| 浮层气泡 / Toolbar | `thin()` | 20dp | 1.5~1.8× |
| 轻量提示 / 强调 | `ultraThin()` | 16dp | 1.6~2.0× |

**必须附带噪点** `noiseFactor 0.03~0.06`：纯高斯模糊在 8bit 色深下会产生可见色带，iOS 的玻璃有极细颗粒感，这是"高级感"的一部分。

**测量方法**

玻璃后方放一张 **1px 黑白棋盘测试图**，截图后：

- 计算玻璃区域的高频能量衰减（`MTF@8px`）；
- 用取色器比较玻璃区域与同位置背景的 HSV 饱和度。

**通过线**

- `MTF@8px ≤ 0.15`（高频基本消失 = 棋盘纹不可辨认）；
- 玻璃后方的**明暗分布仍可感知**（不能糊成纯色块——纯色块说明过度模糊，是常见错误）；
- 饱和度比背景高 **40~80%**；
- 无可见色带（放大 400% 观察平滑渐变区）。

---

### C · 边缘（权重 15%，目标 95%）

iOS 玻璃的边缘是**两条线**，不是一条：

| 位置 | 规格 | 作用 |
|---|---|---|
| 上/左边缘 | 0.5dp（xxhdpi 约 1.5px），白 **55%** | 模拟光从上方来的镜面反射 |
| 下/右边缘 | 0.5dp，白 **18%** | 模拟厚度造成的暗边 |
| 渐变方向 | 135°（左上→右下） | 单侧纯色描边 = 廉价玻璃拟态的标志 |

**测量方法**

截取玻璃上边缘，沿垂直方向取 5px 像素序列，读亮度值。

**通过线**

- 亮度呈 **"递增 → 峰值 → 骤降"** 的梯度（不是平台状）；
- 峰值亮度比玻璃内部亮 **≥12%**；
- 下边缘存在可测暗边（亮度低于内部 ≥6%）；
- **上下边缘亮度不对称**（对称 = 未做方向性，FAIL）。

---

### D · 层级与配色（权重 15%，目标 90%）

**三条硬规则（违反即红线，见 §3）**

1. 玻璃**只用于导航层**（顶栏、底栏、Tab、悬浮操作、Sheet、对话框）；
2. 玻璃**不叠玻璃**；
3. 同屏主玻璃面 **≤3 个**。

**自适应染色**：采样背景平均亮度，`tint` 在 ±8% 内调整；深色主题 `tintDark` 黑 18%~28%，浅色 `tintLight` 白 12%~18%。

**投影**：L3 双层（环境 8dp + 接触 16dp），L2 单层，L1 描边替代。

**测量方法**

把 App 桌面壁纸依次换成 **纯白 / 纯黑 / 高饱和纯色** 三张，逐一截图，测量玻璃面上文字的对比度。

**通过线**

- 三张壁纸下，玻璃面文字对比度均 **≥4.5:1**（WCAG AA）；
- 玻璃面在纯白背景下**不发灰**、在纯黑背景下**不过曝**；
- 投影在浅色背景可见、深色背景不突兀（深色下应转为微弱外发光）。

---

### E · 动效（权重 20%，目标 88%）

| 场景 | 时长 | 曲线 | 附加 |
|---|---|---|---|
| 按压反馈 | 100ms | 线性 | `scale → 0.97` |
| Tab 切换 | 300ms | `CubicBezierEasing(0.32, 0.72, 0, 1)` | 玻璃形变 |
| 页面推入 | 350ms | 同上 | |
| Sheet 升起 | 400ms | `spring(dampingRatio=0.85, stiffness=300)` | 背景缩放 0.98 |
| 高光随滚动 | 跟随 scroll offset | 无独立时长 | |
| 数字变化 | 250ms | `FastOutSlowIn` | 等宽数字 |

**测量方法**

录屏 **120fps**，逐帧定位动画起止帧，计算实际时长；从 3 个中间关键帧反推贝塞尔控制点。

**通过线**

- 时长误差 **≤±30ms**；
- **无任何 >400ms 的动效**（当前代码 `AnimationConstants` 存在 500ms 颜色过渡，必须收紧）；
- L3 中端机掉帧率 **<1%**；
- 曲率为 `(0.32, 0.72, 0, 1)` 而非 `FastOutSlowIn`——两者观感差异明显，`FastOutSlowIn` 会显得"安卓味"。

---

### F · 排版（权重 10%，目标 90%）

| 项 | 规格 |
|---|---|
| 金额 / 数字 | 字重 600~700，`FontFeatureSetting("tnum")` **等宽数字** |
| 正文 | 400 |
| 辅助信息 | 500 |
| 大标题字距 | **-0.5 ~ -0.8sp**（iOS 大字号收紧字距） |
| 行高 | 字号的 1.2~1.3 倍 |

**测量方法**

让金额从 `1,234.56` 刷新到 `9,999.99`，录屏观察数字容器是否横向位移。

**通过线**

- 数字变化时**小数点与千分位定位点零位移**（不等宽必然跳动，这是财务类 App 最刺眼的破绽）；
- 标题字距为负值（正值会显得"松垮"，安卓默认常为正）；
- 字号阶梯为 11/13/15/17/20/28/34sp（对应 iOS 的 caption2/body/headline/title…）。

## 3. 红线（一票否决，任一违反则整体不通过）

以下 6 条**无论其他维度得分多高**，只要命中一条即判定验收失败：

| # | 红线 | 为什么是红线 |
|---|---|---|
| R1 | 圆角使用 `RoundedCornerShape` 圆弧 | 接缝曲率突变，一眼看出"不是 iOS" |
| R2 | 玻璃叠玻璃 | 视觉噪音，直接沦为廉价玻璃拟态 |
| R3 | 内容层（列表行、图表）使用玻璃 | 破坏层级，违反 HIG 第一条 |
| R4 | 数字非等宽，刷新时跳动 | 财务 App 最刺眼的破绽 |
| R5 | 用 `Modifier.blur` 做背景模糊 | 会连自身文字一起糊掉（它是模糊自身内容） |
| R6 | 同屏玻璃面 >3 个 | 超出即降级为半透明实色 |

## 4. 验收执行流程

| 阶段 | 时机 | 动作 | 产出 |
|---|---|---|---|
| 基线 | 阶段 2 第 1 周 | 用 `L3/L2/L1` 三档机各跑一次静态截图，与本文件 §1 打分 | 基线分（预期 65~75） |
| 迭代 | 阶段 2 每周 | 只对失分维度调参，不整体重做 | 分数趋势 |
| 定稿 | 阶段 2 结束 | 全维度打分 + 红线自查 | **验收报告** |
| 回归 | 阶段 4 末 | 重跑一次，防打磨阶段引入退化 | 回归分 |

**参照物**：以 Apple HIG 公开截图 + iOS 26 设计资源为参照。若你有 iPhone 实机，录屏对照可将 E 维度判据从"反推曲线"提升为"逐帧比对"，精度更高——**这一点待你确认是否有 iPhone 可用于对照**。

## 5. 测试机型矩阵（开工前必须确认）

| 档位 | 代表机型 | 需覆盖维度 | 通过线 |
|---|---|---|---|
| **L3** | 骁龙 8 Gen2+ / 天玑 9200+，API 34+ | A~F 全部 | **≥92%** |
| **L2** | 骁龙 778G / 天玑 1080，API 34 | A、C、D、E、F（B 降为 18dp 且无折射） | **≥85%** |

> `minSdk 34` 后 **L1 档已不存在**，机型矩阵由三档减为两档，测试工作量同步减少。
> 「低端 GPU」判定不看型号，看 `ActivityManager.isLowRamDevice` + 首帧渲染耗时，运行时自动选档。

⚠️ **待确认**：你手上有哪几档设备？若只有一台 L2 机，则 L3 的 92% 无法实测，只能靠代码审查 + 参数推断——这会让验收可信度下降，需提前知情。

## 6. 不可达项登记（明确放弃，不再尝试）

| 项 | 可达 | 原因 | 处置 |
|---|---|---|---|
| 高光随设备姿态流动 | 30% | Android 无系统级统一光场，各 OEM 无统一环境光 API | 不做陀螺仪伪实现（已决策）。改用静态 135° 方向渐变 + 滚动联动替代 |
| 形状融合形变（Metaball） | 50% | 无 `GlassEffectContainer` 等价物 | 仅 Tab 切换与 Sheet 做 Path 插值近似，其他场景不做 |
| 系统级动效一致性 | 70% | 各厂商 ROM 有自己的转场 | 只保证 App 内部一致，不试图统一系统手势 |
| 逐像素对照 | — | 渲染管线差异 | 已决策不做 |

# 界面完整性审计（2026-10-31）

对照 `REBUILD_PLAN.md` 第 5.1/5.2 节与阶段 3 页面表，逐项核对当前实现。
结论：**方案 10 个页面中，3 个完整、4 个部分、3 个完全缺失**；
另有 **4 项架构级缺口**会直接卡住剩余页面，不是补 UI 能解决的。

---

## 二、偏差（不是缺失，是实现与方案不一致）

| # | 偏差 | 影响 | 处置建议 |
|---|---|---|---|
| D1 | `TradeType` 只有 3 类（买入/卖出/分红），方案要求 5 类（另含再平衡/追加/取出） | 再平衡执行后无法把"这次调仓"记成一条独立类型的流水，统计口径会混入普通买卖 | 增补枚举值 + 数据库默认值，`trades` 表已有 type 字段，属增量改动 |
| D2 | `MarketClock`（交易时段判定，7 个单测覆盖）**生产代码零引用** | 方案 P0 要求"仅交易时段自动刷新"，现在既没有自动刷新，时钟也白写了 | 接入刷新调度器（见 D3） |
| D3 | **没有任何定时刷新** | 方案 P0：3s/5s 固定频率 + 交易时段 + 后台降频 + 下拉刷新，四条全缺。当前只有手动点"刷新行情" | 补调度器 + 下拉刷新 |
| D4 | 时间防篡改（SNTP 三级降级 + elapsedRealtime）完全未实现 | 用户改系统时间可伪造当日收益 | 排在发布前，属 P0 |
| D5 | 概览页无"本金" | 用户看不到"我投了多少"，只看得到市值与盈亏 | 汇总卡加一栏 |
| D6 | 设置缺"刷新频率""初始投资日期" | 方案 5.2 明确列出 | 随 D3 一起补 |
| D7 | 导航用手写 `Overlay` 而非 NavHost | 当前只有 2 个覆盖页，够用；到 5 个以上会失控 | 补到第 4 个覆盖页时改 NavHost |
| D8 | `NavChart` 从 `feature:charts` 下沉到 `core:ui` | 详情页也要画同一条曲线，放 feature 会导致 feature 互相依赖 | 保留该调整，更新架构文档 |
| D9 | 日历视图**未新建独立页面**，而是作为走势页第三维度 | 方案把"日历视图"列为第 7 个页面，但未规定它必须有独立入口。做成第六个 Tab 会违反 §8.4 定的五项导航结构 | 保留该实现。理由：日历与收益走势读同一张 `net_value_snapshot`、回答同类问题（"过去发生了什么"），合并后底部导航仍是五项 |
| D10 | 日历的"节假日标注"改为**按有无快照判定** | 方案 §5.1 要求"节假日标注"。硬编码节假日表会因每年调休失效（M3 风险项已列） | 保留。非交易日没有行情就没有快照，格子不填色，语义比"标注节假日"更准：它同时覆盖周末、节假日、停牌 |
| D11 | 内容层容器由 `GlassPanel` 改为新建的 `SolidCard`（29 处） | `VISUAL_ACCEPTANCE.md` 红线 R3 明确"内容层（列表行、图表）使用玻璃"违规，此前实现全线违反 | 已修正。判定标准：会滚动的 = 内容层 → SolidCard；不滚动的 = 导航层 → GlassPanel |

## 四、建议补充的界面清单

### P0 — 不补则方案不成立

1. **目标仓位配置页**：基金级 `targetRatio` 输入、合计实时校验（须为 100%）、等权/市值加权快捷值、偏离度可视化。再平衡页的输入前提。
2. **交易历史页**：全部流水按时间倒序，按月分组、按类型筛选、按基金筛选，支持删除单笔。
3. **备份 / 恢复流程页**：导出（口令设置 + 强度提示 + 二次确认）→ 恢复（口令输入 → 解密 → 覆盖前确认 → 结果汇总 + 条数校验）。
4. **组合收益走势**（作为图表页第二维度，不一定新开页面）：总资产/收益率随时间的曲线，周/月/年切换。

### P1 — 影响完整度

5. ~~**日历视图页**~~ **已实现**：作为走势页第三维度（月历日格 + 当月汇总 + 翻月）。节假日判定改用「有无快照」而非硬编码节假日表。
6. **首次引导页**：3 屏（记什么 / 怎么记 / 数据在哪），末屏一键灌样例或直接开始。
7. **操作日志页**：按时间倒序列出 `operation_logs`，按 action 筛选。数据已经在写，只差一个列表。
8. **行情刷新设置**：频率档位、仅交易时段开关、后台降频开关。依赖 G3。

### P2 — 锦上添花

9. **数据管理页**：清空全部数据、重建示例、导出 CSV。
10. **再平衡执行记录**：把"某次调仓的买卖清单"存成一条可回溯的记录。

## 五、建议的执行顺序

```
G1 组合快照表  ──┬─→ 4 收益走势   ✅ 已完成
                 └─→ 5 日历视图   ✅ 已完成
G3 刷新调度器  ──┬─→ 8 刷新设置
                 └─→ D3/D2 自动刷新
G2 交易类型  ────┬─→ 10 再平衡记录
                 └─→ 追加/取出资金
6 目标仓位 ──────→（解锁再平衡的真实用法）
2 交易历史页
3 备份恢复流程
```

理由：G1 和 G3 是**数据基础**，先补；目标仓位虽然只是一个表单，但它是再平衡功能的前置，
不做的话再平衡页永远只能看默认目标；备份恢复涉及"用户唯一一份数据"，风险最高，
值得单独做一个完整流程而不是两个按钮。

## T-002 收口：放弃旧密钥，统一用新密钥

### 结论
旧签名密钥（证书 `L=Donglizhen`）**文件找回来了，但口令救不回来**，因此放弃。
装过 v1.6.5 的设备需卸载重装一次，此后统一用 `CN=XSTZ` 新密钥覆盖升级。

### 取证留档（值得记，别再重复劳动）
- 官方基线：GitHub Releases 的 `xstz-v1.6.5.apk`，sha256 `1b9d5e1e…`。
  `apksigner verify --print-certs` 得旧证书 SHA-256：`f8f7c99f95838d337d8c92fb4e01b6dc9a6e811c483a6a357fdd4db672da1d73`。
  **注意**：APK 是 v2 签名，没有 `META-INF/*.RSA`，`keytool -printcert -jarfile` 读不了，必须用 `apksigner`。
- 旧密钥本体：E 盘回收站 `$Recycle.Bin/<SID>/$RCB9Y45/密钥`（PKCS12，2516 字节，MD5 `ab2e1a11…`）。
  回收站的 `$I*` 是元数据（含原始路径，UTF-16），`$R*` 才是内容——可用来还原“这文件原本在哪”。
- 口令确实无处可寻：git 历史（旧仓库 21 提交，`keystore.properties` 从未入库）／IDE 配置／
  Windows 凭据管理器／Gradle `executionHistory.bin`（只有 `storePasswordHash`）／PowerShell 历史／文本笔记。
- 自写 PKCS12 MAC 校验器（RFC 7292 KDF）试了约 6.2 万条候选，零命中。
  方法本身先用“已知口令 + 已知密钥”自检过，判定可信。

### 清理
- 旧密钥全部副本销毁：本体、`xstz-release.keystore` 同名副本、`.signing/` 中间态、会话备份内的多代副本；
  回收站里 6 份做了全零覆写。
- AVD 全部删除：`xstz`(3.8G) + `xstz_api36`(2.6G)，共释放 **6.4 GB**。系统镜像 `android-36` 保留，可随时重建。

### 踩坑（真实且反直觉）
1. **删除会被“先备份再删”拦截**：在 `.workbuddy/workspace/sessions/<id>/modify_backup` 里删文件，
   工具会先把原内容复制一份再删除，于是每删一次就多一代（文件名层层嵌套 `46.d.xxx.46.d.yyy…`）。
   写入同理（前缀变成 `46.m.`）。**在这种目录里追着删是死循环**，正确做法是让用户关会话后整目录删除。
2. **`rm` 报“Permission denied”未必是权限问题**：ACL 显示 FullControl、属性 Normal，但目录被独占句柄占着时，
   子文件删除全失败；把**目录本身改名**（Move-Item）后锁释放，再删就成功了。这招比 takeown/icacls 快。
3. **回收站可能极大**：本机 C 盘 `$Recycle.Bin` 有 7.5 万个条目，全量 md5 扫描会超时。
   按**文件大小**先筛（密钥就那几种固定大小），再算 md5，10 秒就能扫完。
4. 进程明明没了却删不掉文件时，用 `Get-CimInstance Win32_Process` 按**命令行**匹配比按进程名可靠。

## Baseline Profile 采集：9 个坑全排完，卡在 MIUI（提交 b0e4a34）

跑 `:benchmark:connectedBenchmarkAndroidTest` 连续踩了 9 个真问题，全部已修并固化进代码：

1. 混淆状态不一致（App 开 R8、测试包没开）→ checkTestedAppObfuscation 失败
2. **AGP 9.1 的 com.android.test 不应用 buildTypes.proguardFiles**（规则文件根本不进 R8 输入，
   中间产物里查不到任何规则痕迹）→ 放弃给测试包加规则，两边都不开 R8；
   改在 gradle.properties 开 `android.experimental.art-profile-r8-rewriting=true`，
   让 release 打包时按 mapping 重写规则名
3. 测试包 debug 签名 vs App release 签名 → 插桩被拒；测试模块改读 keystore.properties 共用密钥
4. BaselineProfileRule 会授予 READ/WRITE_EXTERNAL_STORAGE，App 没声明 → pm grant 静默空操作后判定失败；
   在 app/src/benchmark/AndroidManifest.xml 声明（仅该变体）
5. runner 参数 `androidx.benchmark.profiling.mode=baselineprofile` 不是合法枚举 → 删掉，规则自己决定
6. **测试与 App 同进程**：com.android.test 会按 targetProjectPath 把 instrumentation 的
   targetPackage 钉成 App；基准测试杀 App 测冷启动时自杀 →
   `experimentalProperties["android.experimental.self-instrumenting"] = true`
7. 清单手写 `<instrumentation>` **没用**：AGP 在清单合并之后注入，tools:replace 也压不住。
   判断方法：`aapt2 dump xmltree --file AndroidManifest.xml <apk>` 看 targetPackage
8. 生成器点「图表」Tab，实际文案是「走势」→ By.text 匹配不到会静默跳过，profile 缺路径
9. 生成器等「资产概览」，实际标题是「概览」

## 反转：Baseline Profile 最终跑通了（提交 1673a87）

上一节把卡点归因为 MIUI，**判断错了**。真凶是两个，都与设备无关：

1. **`BaselineProfileRule.collect` 不会替你启动应用**。collect 块里必须显式
   `pressHome()` + `startActivityAndWait()`。漏了它，全程没有目标进程，
   最后 `pm dump-profiles` 只回 "Waiting for app processes to flush profiles..."，
   profile 恒 0 字节，但抛的是 IllegalStateException。
   —— 手机和模拟器报**一模一样**的错，正是"根因在脚本不在设备"的证据，当时没抓住。
2. **androidx.benchmark 1.3.3 解析不了 API 36 的 frame timeline**，
   报 `Unable to confirm activity launch completion []`。升 **1.4.1** 通过。
   （framestats 数据本身是好的，手工 dump 验证过。）

辅助项：模拟器采集要 `suppressErrors=EMULATOR`。

**结果**：
- `app/src/main/baseline-prof.txt`：25 行手写种子 → **18642 条真实规则**
- release 包含 `assets/dexopt/baseline.prof`(8.1KB) + `baseline.profm`(1.0KB)
- 冷启动真机 8 次：339/228/211/189/202/197/203/185ms，**中位 ≈200ms**（目标 <1.2s）

**方法论教训（比结论更重要）**：
多个设备报同一个错时，先怀疑代码，不要先怀疑设备。
"OEM 差异"是很贵的假设，一旦采信就会停止排查真正的 bug。

**环境现状**：为跑采集重建了 AVD `xstz`（720x1600，x86_64），用完已 `emu kill`，
AVD 文件仍在 `C:/Users/21063/toolchains/avd`（约 3.8G）。若不需要可再删。

## 覆盖率收口 + 两个真缺陷（提交 5b2a9e3）

### 重要教训：buildDirectory 不能跨盘
把 `layout.buildDirectory` 指到 D 盘后，`assembleDebug` 能过，但
`testDebugUnitTest` 直接报
`this and base files have different roots: D:/.../build/domain 和 C:/.../core/domain`。
Gradle 测试任务要按相对路径解析 source set，跨盘算不出来。
**所以「构建产物放 D 盘」与「跑单测/统计覆盖率」互斥**，除非整个工程搬到 D 盘。
已回滚，产物留在工程内；SDK / Gradle 缓存 / AVD 三项迁移不受影响。

### 测试逼出来的两个缺陷（都比覆盖率数字有价值）
- **T-004 北交所股票完全不识别**：`STOCK` 正则里 `43|8[378]` 和其它段共用了 `\d{3}`，
  只能匹配 5 位，而 A 股代码统一 6 位 → `isStock` false → `tencentQuoteSymbol` null
  → 行情压根不查。附带补了 `stockExchange` 的 `bj` 前缀。
- **T-005 沪市国债 019xxx 被当成场外基金**：`^(019|10)\d{4}$` 要求 019 后跟 4 位（7 位），
  国债是 6 位。深市 `10xxxx` 恰好正确，所以只坏了沪市，问题被掩盖。
- 共同特征：**不报错，只表现为"暂无数据"**。这类问题只能靠边界测试发现，功能测试查不出来。
- 写测试时踩到的坑：`class CodeClassifierTest` 已存在于 `QuoteParserTest.kt` 里，
  新建同名文件会 Redeclaration 编译失败。查测试覆盖范围要 grep 类名，不能只 ls 文件名。

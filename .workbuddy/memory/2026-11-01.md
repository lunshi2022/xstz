# 2026-11-01

## T-002 收口：放弃旧密钥，统一用新密钥

### 结论
旧签名密钥（证书 `L=Donglizhen`）**文件找回来了，但口令救不回来**，因此放弃。
装过 v1.6.5 的设备需卸载重装一次，此后统一用 `CN=XSTZ` 新密钥覆盖升级。

### 取证留档（值得记，别再重复劳动）
- 官方基线：GitHub Releases 的 `xstz-v1.6.5.apk`，sha256 `1b9d5e1e…`。
  `apksigner verify --print-certs` 得旧证书 SHA-256：`f8f7c99f95838d337d8c92fb4e01b6dc9a6e811c483a6a357fdd4db672da1d73`。
  **注意**：APK 是 v2 签名，没有 `META-INF/*.RSA`，`keytool -printcert -jarfile` 读不了，必须用 `apksigner`。
- 旧密钥本体：E 盘回收站 `$Recycle.Bin/<SID>/$RCB9Y45/密钥`（PKCS12，2516 字节，MD5 `ab2e1a11…`）。
  回收站的 `$I*` 是元数据（含原始路径，UTF-16），`$R*` 才是内容——可用来还原“这文件原本在哪”。
- 口令确实无处可寻：git 历史（旧仓库 21 提交，`keystore.properties` 从未入库）／IDE 配置／
  Windows 凭据管理器／Gradle `executionHistory.bin`（只有 `storePasswordHash`）／PowerShell 历史／文本笔记。
- 自写 PKCS12 MAC 校验器（RFC 7292 KDF）试了约 6.2 万条候选，零命中。
  方法本身先用“已知口令 + 已知密钥”自检过，判定可信。

### 清理
- 旧密钥全部副本销毁：本体、`xstz-release.keystore` 同名副本、`.signing/` 中间态、会话备份内的多代副本；
  回收站里 6 份做了全零覆写。
- AVD 全部删除：`xstz`(3.8G) + `xstz_api36`(2.6G)，共释放 **6.4 GB**。系统镜像 `android-36` 保留，可随时重建。

### 踩坑（真实且反直觉）
1. **删除会被“先备份再删”拦截**：在 `.workbuddy/workspace/sessions/<id>/modify_backup` 里删文件，
   工具会先把原内容复制一份再删除，于是每删一次就多一代（文件名层层嵌套 `46.d.xxx.46.d.yyy…`）。
   写入同理（前缀变成 `46.m.`）。**在这种目录里追着删是死循环**，正确做法是让用户关会话后整目录删除。
2. **`rm` 报“Permission denied”未必是权限问题**：ACL 显示 FullControl、属性 Normal，但目录被独占句柄占着时，
   子文件删除全失败；把**目录本身改名**（Move-Item）后锁释放，再删就成功了。这招比 takeown/icacls 快。
3. **回收站可能极大**：本机 C 盘 `$Recycle.Bin` 有 7.5 万个条目，全量 md5 扫描会超时。
   按**文件大小**先筛（密钥就那几种固定大小），再算 md5，10 秒就能扫完。
4. 进程明明没了却删不掉文件时，用 `Get-CimInstance Win32_Process` 按**命令行**匹配比按进程名可靠。
